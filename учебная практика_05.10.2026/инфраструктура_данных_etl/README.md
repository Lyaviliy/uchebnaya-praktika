# Инфраструктура данных и ETL (База данных в 3NF)

СУБД: PostgreSQL. Стиль именования: snake_case, таблицы во множественном числе.

## 1. Схема (3НФ) — `db/schema.sql`
| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `partner_types` | ООО, ИП, АО, ЗАО, ПАО | `name` UNIQUE |
| `partners` | партнёры | FK → partner_types, `inn` UNIQUE + CHECK 10/12 цифр, `email` UNIQUE, `rating` ≥ 0 |
| `product_types` | типы продукции и коэффициент для расчёта сырья | `coefficient` > 0 |
| `material_types` | типы материалов и % брака | 0 ≤ `defect_percent` < 100 |
| `products` | справочник номенклатуры | FK → product_types, `price` DECIMAL(12,2) |
| `sales_history` | история реализации | FK → partners (CASCADE), FK → products (RESTRICT), `amount` DECIMAL(14,2), `quantity` > 0 |

3НФ: тип организации вынесен из названия партнёра в справочник, в продажах хранятся только ссылки на партнёра и товар, без копий их названий и цен.

## 2. ETL
Сырые файлы сначала загружаются **как есть** в промежуточные таблицы схемы `staging` (все поля TEXT), а очищаются **SQL-запросами** в `db/etl.sql`.

| Файл | Аномалия | Как устранено (`etl.sql`) |
|---|---|---|
| partners_raw.csv | пробелы по краям названия и email | `btrim` |
| | тип организации слит с названием | `split_part` → справочник `partner_types` |
| | мусор `...` и двойные пробелы («ИП ...Петров  A.B.») | `regexp_replace` |
| | инициалы набраны **латиницей** (A.B.) | `translate` только для хвоста-инициалов → А.В. |
| | email в разном регистре | `lower` |
| products_raw.csv | кодировка **Windows-1251** вместо UTF-8 | `ENCODING 'WIN1251'` при загрузке |
| | кавычка-дюйм в `Монитор 27"` без экранирования — строгий CSV падает | загрузка в текстовом режиме, снимается только парная обрамляющая кавычка |
| | пробелы по краям названия | `btrim` |
| sales_history_raw.csv | **5 форматов даты**: `25.10.2023`, `2023/10/26`, `28-10-2023`, `2023.10.29`, ` 2023-10-30 ` | `btrim` + `translate('./','--')` + `to_date` по двум шаблонам → ГГГГ-ММ-ДД |
| | продажа 1003 партнёру **999**, которого нет | исключена, выводится в отчёте |
| все | переносы строк Windows (CRLF) | учтено при загрузке |

Коэффициентов типов продукции и процентов брака в исходных файлах нет — справочники заполняются в `etl.sql` (Ноутбуки 2.5, Смартфоны 1.4, Мониторы 3.1; Пластик 0.8%, Металл 0.35%, Стекло 1.5%).

## Запуск через psql
```bash
psql -U postgres -d praktika -f db/schema.sql
psql -U postgres -d praktika -f db/staging.sql
psql -U postgres -d praktika -f db/load_raw.psql
psql -U postgres -d praktika -f db/etl.sql
```
Или одной командой в приложении: `npm run db:init` (папка `ui_навигация_crud`), результат тот же — проверено сравнением.

## Результат (`etl_result.txt`)
partners 5, products 3, sales_history **5 из 6** (1003 отброшена: партнёр 999 не существует).
